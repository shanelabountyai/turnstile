# Accessibility lens — Turnstile live release (main 9d8b434)

Scope: WCAG 2.1 AA on the clone-owned Turnstile screens (/demo, org home, events, event, buy, box office, door, ledger, member error page). Read-only; nothing in the repo was changed.

## How this was checked

**Automated (re-run this session, against the production build in `.next`, local Postgres `turnstile_shots`):**
- axe-core 4.13.0 from `node_modules` (same loading approach as `e2e/axe.ts`, `bypassCSP`), tags wcag2a/2aa/21a/21aa + best-practice, on 12 page states x 1280 and 390 x light and dark = 48 runs: `/demo`, `/o/acme`, `/o/acme/events`, event, buy (no customer), buy as C-0002 (seat grid), box office, box office with ORD-00001 open, door, ledger, event as member, member's error page after Set clock.
  - Result: **0 violations on every Turnstile event screen in both schemes and both widths.** The only violations were on `/o/acme` (`skip-link`, `region`; A11Y-3).
  - axe "incomplete" (could not decide) colour-contrast: event page 4 nodes (4th column of the tiers table) and ledger 5 nodes (caption, two header cells) at 390 only — these cells sit inside a horizontally scrolled `.table-wrap`, partly off-screen, so axe cannot sample the background. Not a finding; `design:contrast` reported 0 pairs under floor this session.
- Keyboard pass (Playwright, Tab from a blurred body at scroll 0, focused element and computed outline recorded per stop) on /demo, event, buy-as-customer, box office, door.
- Target-size scan at 390 (every visible focusable under 44 px, plus its wrapping label's box).
- Live-region check on the door: the same ticket code scanned twice before doors; a MutationObserver on `[aria-live]` saw the assertive region re-filled both times ("Do not admit. Doors are not open yet…"), and focus stayed in the code field.

**By inspection:** `src/components/{announce,countdown,ui,pill,stripe-pay,nav-link}.tsx`, `src/app/turnstile.css`, buy/door/event page markup, `src/app/error.tsx`, screenshots 02, 06-390, 13, 14.

**Not run:** a real screen reader (NVDA/VoiceOver), browser zoom 200% / 320 px reflow, Windows high contrast. Stripe Elements iframe was **not rendered** (no publishable key in any local run, by design), so its accessibility is unreviewed.

Clean-up: server stopped, temporary `.env.local` deleted, `git status --porcelain` empty.

## Findings

### A11Y-1 — Member pressing Set clock gets a page that does not say what went wrong (3.3.1, 2.4.2)
- Severity: **Major**
- Where: `src/app/o/[org]/events/[event]/page.tsx:123-124` (the form a member can submit), `src/app/error.tsx:4-11` (what renders); screenshots `13-member-set-clock-1280.png`, `13-member-set-clock-390.png`.
- Observed: after the 500, the whole org layout is gone: no org bar, no event tabs, no skip link, only `<main><h1>Something went wrong</h1><p>Error id: …</p><button>Try again</button>`. Focus is left on `<body>`. The document title stays "Event · Turnstile" while the content is an error. Nothing states the cause (members cannot move the clock) or how to fix it. axe passes it (0 violations); the problem is content, not markup.
- Why it matters: for a screen reader user the error is not identified in text (3.3.1) and the page title describes a different page (2.4.2). "Try again" repeats the same refused action. A keyboard user must use browser Back to get out. The member account is one of the six on `/demo`, so a reviewer can reach this.
- Recommended fix: the fix already listed in NEXT.md. Have the clock action return a refusal (a `Notice` plus `Announce`, as the buy and box results do) instead of throwing `AuthzError`, or hide or disable Set clock for members with a sentence saying why. Optionally give `error.tsx` a `<title>` and a link home.
- Verified (reproduced: 48-run script, focus on body, title read, HTML captured).

### A11Y-2 — The countdown's spoken warnings read "left on time left on H-…"
- Severity: **Minor**
- Where: `src/app/o/[org]/events/[event]/buy/page.tsx:168` passes `label={\`time left on ${h.hold}\`}`; `src/components/countdown.tsx:36` builds `` `Two minutes or less left on ${label}.` `` and `` `Time is up on ${label}.` ``.
- Observed: the polite region speaks "Two minutes or less left on time left on H-2AF305D1." and "Time is up on time left on H-2AF305D1." Also, at zero `router.refresh()` fires in the same render that sets "Time is up". When the hold has expired, the server re-render moves it to the ended list and unmounts that live region, so the zero announcement may be cut off. That second part is Suspected: it depends on the round-trip time and was not observed with a screen reader. The two-minute warning is also never spoken when the page loads with 120 s or less left (`seconds > 120` guard). That fits D-39's "speak once" intent, but it means a reload close to expiry gets no warning.
- Why it matters: D-39 relies on the spoken warning to make an unextendable hold acceptable under 2.2.1's essential exception. The warning should read cleanly and should arrive.
- Recommended fix: pass `label={h.hold}`, or change the template to "on hold H-…". Put the zero message in a region that survives the refresh, e.g. the page-level `Announce` keyed on expired holds.
- Verified (string, by reading the code) / Suspected (zero-announcement race).

### A11Y-3 — Skip link on the org home points at nothing (2.4.1)
- Severity: **Minor**
- Where: `src/app/o/[org]/layout.tsx:16` (`href="#main"`) and `src/app/o/[org]/page.tsx:8` (`<main>` with no `id="main"`); screenshot `02-org-home-1280.png`.
- Observed: axe `skip-link` (target missing) and `region` violations on `/o/acme` at all four width/scheme combinations. Every events page has `<main id="main">` and passes.
- Why it matters: `/o/acme` is where a visitor lands after one-click sign-in on `/demo`, so the first skip link a keyboard user tries does nothing.
- Recommended fix: add `id="main"` to that `<main>`. Better, replace the placeholder "Nothing here yet" home with the events list or a redirect to it; the file's own comment says the clone replaces this page. Consider moving `id="main"` into the layout so a page cannot forget it.
- Verified (axe, 4 runs).

### A11Y-4 — Seat checkbox names do not contain their visible label (2.5.3 Label in Name)
- Severity: **Minor**
- Where: `src/app/o/[org]/events/[event]/buy/page.tsx:270-271`; screenshot `06-buy-hold-c0001-390.png`.
- Observed: the visible text is the seat number ("1", "2" …), but `aria-label` overrides it with "A-A-01 open". The name contains "01", not the word "1". A speech-input user who says "click 1" or "check 7" may not hit the seat.
- Why it matters: 2.5.3 asks that the accessible name start with or contain the visible text. The section and row context is useful, so it should be added after the number, not used in place of it.
- Recommended fix: drop the `aria-label` and add visually hidden text around the number, e.g. "1" followed by `<span class="sr-only">, row A, section A, open</span>`. The group already names the row.
- Verified (by reading; names confirmed in the keyboard pass, e.g. "A-A-01 open").

### A11Y-5 — Seat grid: 72 Tab stops before "Hold seats", and taken seats are skipped by Tab
- Severity: **Minor** (not a 2.1 AA failure; a usability cost for keyboard and screen reader users)
- Where: `src/app/o/[org]/events/[event]/buy/page.tsx:262-279`.
- Observed: in the keyboard pass on buy-as-customer, stops 26 to 60 were all seat checkboxes and the run ended inside row C. Reaching "Hold seats in A" takes one stop per open seat (72 in an empty section). Taken seats are `disabled`, so they never get focus. A Tab user hears only open seats and cannot tell from Tab alone which seat would be left stranded, yet that is exactly what ORPHAN_SEAT judges. The per-row "N open" count and browse mode still expose them.
- Why it matters: picking adjacent seats while avoiding an orphan is the main task on this screen. Keyboard users get the most steps and the least information.
- Recommended fix (pick one): one Tab stop per row with arrow keys between seats (roving tabindex), or a "Skip to Hold seats" link before the grid. To make taken seats discoverable, use `aria-disabled="true"` plus a refusal on submit instead of `disabled`, so they stay focusable and are announced as "sold" or "held".
- Verified (keyboard pass).

## Checked and clean
- **axe-core:** 0 violations on events, event, buy (with and without a customer), box office (empty and with an order), door, ledger, /demo, event as member, and the member error page. Each at 1280 and 390, light and dark.
- **Visible focus:** every recorded stop had a 3 px solid `--ac` outline (`turnstile.css:111`). Seat labels show it through `.seat:focus-within` (`:270`). The skip link appears on focus (`:305-306`). Screenshot `14-event-focus-tab3-1280.png` agrees. The one stop with `outline: none` was a sub-field inside Chromium's native `datetime-local` control, which draws its own focus.
- **Focus order:** skip link → wordmark → org nav → event tabs → page content, in DOM and visual order on event, buy, box and door. /demo tabs through the six account buttons in order. On the door, `autoFocus` puts focus in Ticket code, and it stays there after each scan.
- **Target size at 390:** seat labels are 44 x 44 (the checkbox fills the label). Box office refund checkboxes are 20 x 20 inside labels 150 x 44. Only inline text links are below 44 px tall, which 2.1 AA allows (2.5.5 is AAA).
- **Form labels:** every input, select and number field has a wrapping `<label>` (buy :90, :236, :241, :286, :315, :321; door :68; event :123). The seat fieldset has a legend and per-row `role=group` names.
- **Results and errors:** command results show as a visible `Notice` with title and code and are spoken through `Announce` (assertive for refusals: buy :118, box :132, door :63). Repeated identical door results were re-announced (MutationObserver test). Stripe errors use `role="alert"` (`stripe-pay.tsx:40`).
- **Countdown:** non-live `role="timer"` plus a separate polite region (D-39); reasoning recorded (subject to A11Y-2).
- **Colour is never the only signal:** pills and notices carry glyph and word (`pill.tsx`). Seats use outline, fill plus strike-through, or ✓.
- **Headings and landmarks:** one `<h1>` per page via `PageHeader`; sections tied by `aria-labelledby`; named navs ("Event screens", "Balcony sections"); `aria-current` on the current tab and step; scroll tables are named, focusable regions.
- **Page titles:** distinct per screen (Events, Event, Buy tickets, Box office, Door, Ledger).
- **Motion:** only short transitions, all removed under `prefers-reduced-motion` (`turnstile.css:311`).
- **Images and alt text:** no `<img>` on the Turnstile screens; glyphs are CSS or text.
- **Phone-width nav:** the org nav and event tabs scroll sideways (`turnstile.css:298`); every link stays reachable by Tab.
