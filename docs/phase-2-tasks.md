# Phase 2 — Schema, cast path, Stripe boundary, recount (draft at the Phase 1 gate; for Shane's review)

Phase 1's engine is the spec made executable in TypeScript. Phase 2 makes it true in a database: the same rules, one transaction per command, state the engine can recount from, and a Stripe boundary that never needs a key where the agent runs (D-5, D-20..D-23). Stripe keys stay on Shane's machine; CI uses `fixtures/stripe/` (recorded payloads, fixture signing secret).

**Owner decision needed before 2.5:** D-26's publishable-key shape (`NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` in clone-owned `src/checkout/env.ts`), and O-8 (the live round trip: one order, one refund).

- [ ] **2.0 Plan check.** Read the foundation's `prisma/schema/core.prisma`, `src/core/db/`, the RLS and `SECURITY DEFINER` patterns in Quorum's `quorum_init` migration and `src/meetings/db.ts`. Write the Phase 2 plan (order, CI-only steps) and stop for review.
- [ ] **2.1 Schema (D-20).** `prisma/schema/turnstile.prisma`: `Event`, `Pool`, `Tier`, `Section`, `Seat`, `Hold`, `Payment`, `Order`, `Ticket`, `WaitlistEntry`, `Refund`, `CommandLog`; every `*_at` is `CHAR(19)` with the D-9 `CHECK`; money `INTEGER` cents; closed enums as Postgres enums; `CommandLog.stripeEventId` unique nullable. *Acceptance:* `prisma validate`; `migrate diff --from-migrations --to-schema --exit-code` empty (CI).
- [ ] **2.2 Guards (D-21).** Hand-written SQL in the clone migration: UPDATE/DELETE refused on `CommandLog`, `Refund`, `Order`; state-transition triggers on `Hold`, `Payment`, `Ticket`, `Seat`, `WaitlistEntry` admitting only the brief's transitions; a `CommandLog` row required per transition (same transaction). *Acceptance:* a test per table proves an illegal UPDATE/DELETE/transition is refused with the trigger's message.
- [ ] **2.3 Load (`turnstile:load`).** Fixture event, seats and customers into an org, write-once (refuses a second load). *Acceptance:* 1,016 seats + 4 tiers + 2 pools + 700 customers; second run refused.
- [ ] **2.4 Cast path (D-22).** `src/checkout/cast.ts`: one transaction per command; `pg_advisory_xact_lock(hashtext(pool_id))` for every pool the command touches; load the event state, run `advance(now)` and the engine's rule for that command against it, write the resulting rows and the `CommandLog`. The engine code is reused, not duplicated: Phase 2 adds a storage adapter (`loadState`/`persistDelta`), not a second rule set. *Acceptance:* two concurrent `HOLD`s for the last floor ticket → exactly one `HELD`, one `SOLD_OUT_POOL` (vitest with two connections).
- [ ] **2.5 Stripe boundary (D-23).** `src/checkout/stripe.ts` behind an interface; `PAY_START` → `paymentIntents.create` (amount from the engine, `metadata.hold_id`, idempotency key = hold id), `PAYING` written only after Stripe returns; `src/app/api/checkout/webhook/route.ts` verifies `Stripe-Signature` (`t`, `v1`, HMAC-SHA256 over `${t}.${rawBody}`, 300 s tolerance against the command's `at`, never the wall clock in tests), dedupes on `event.id` via `CommandLog`, maps `payment_intent.succeeded`/`payment_intent.payment_failed` to `PAY_SUCCEEDED`/`PAY_FAILED` through the cast path; refunds call `refunds.create` after the engine says `REFUNDED` (idempotency key = refund id), `PENDING_PROVIDER` on provider failure with a retry. Tests replace the HTTP boundary with `fixtures/stripe/*.json` (recorded shapes, fixture secret `whsec_fixture_…` committed on purpose). *Acceptance:* signature tests: valid, tampered body, stale `t`, replayed `event.id`; `PAID_AFTER_TIMEOUT` issues the refund call automatically.
- [ ] **2.6 `inventory:eval:db`.** Empty the test database, load the fixture, feed all 2,662 commands through the cast path with Stripe recorded, recount from stored rows, diff against the seven expected files and the commitment. *Acceptance:* 0 differences; the stored-row recount equals the Phase 1 engine's commitment.
- [ ] **2.7 CI.** `inventory:eval:db` on the `off` leg; the concurrency test; signature tests; `migrate diff`. No Stripe secret in CI. *Acceptance:* green run linked in `NEXT.md`.
- [ ] **2.8 `docs/EVAL.md` Phase 2 section.** Concurrency result, signature results, `eval:db` result, and the by-hand live round trip placeholder for Shane.
