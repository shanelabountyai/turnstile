### Engine (Phase 1)

| # | Decision | Why |
|---|----------|-----|
| D-8 | **The engine `src/inventory/` is pure and deterministic.** No database, clock, randomness, network or model client; `npm run inventory:lint` greps for `Date.now`, `Math.random`, `prisma`, `fetch`, `stripe`, `anthropic`, `new Date(`. Commands are evaluated in `(at, cmd_id)` order whatever order they arrive in. **Before** the command at `at` is evaluated, `advance(at)` expires every `HELD` hold or offer with `expires_at <= at`, times out every `PAYING` hold with `pay_timeout_at <= at`, closes waiting entries of GA tiers whose `off_sale_at <= at`, and re-fills waitlists. `reference_alloc.py --shuffle` proves order independence on the fixtures. | Goal 2; a recount must not depend on storage order; the race in D-12/D-13 is only decidable if expiry has a defined place in the tick |
| D-9 | **Timestamps are fixed-width strings on one named calendar axis.** `YYYY-MM-DDTHH:MM:SS`, compared lexically; `event.timezone_label` names the zone and is never used for conversion. TTL and days-before arithmetic is done on that axis as integer seconds (`add_minutes`, `days_before = floor(Δseconds / 86400)`). No `new Date(string)`, no `@db.Date`, no UTC conversion. Windows are half-open: `open_at <= at < close_at`; `at == close_at` is `SALES_CLOSED`. | Bookable's and Quorum's rule; the one place Turnstile differs (TTL arithmetic) stays on the same axis |
| D-10 | **Every command gets one code from a closed set with a stated precedence** (brief §4–§8): 13 OK codes, 41 reject codes, 10 command kinds. A rejected command is recorded in the results and the `CommandLog`, never dropped. `KIND_UNKNOWN` and `RULES_INVALID`/`INPUT_INVALID` are the only fatal-shaped outcomes; the first is a reject, the last two throw. | A box office needs to know *why*; `SOLD_OUT_POOL` and `SOLD_OUT_TIER` are different conversations |
| D-11 | **The pool is the truth.** `tier_remaining = allotment − sold − held`; `pool_remaining = capacity − Σ(sold + held) over the pool's tiers`; `available = min(tier_remaining, pool_remaining)`. `sold` counts tickets in `ISSUED` or `CHECKED_IN`; `held` counts `HELD` and `PAYING` holds *and* offers. Precedence: `SOLD_OUT_POOL` is checked before `SOLD_OUT_TIER`. A refunded ticket returns to its tier and its pool even if the tier is off sale, so another tier can sell the seat (GT-03c/d). Reserved pools derive the same numbers from seat states. | Goal 1; the end-state trap (DOOR 87 remaining, 0 available) |
| D-12 | **Holds are timed to the second; a paying hold runs on its own clock.** `expires_at = created_at + hold_ttl_minutes`; `expires_at <= at` expires (GT-04). `PAY_START` moves `HELD → PAYING`, sets `pay_timeout_at = at + payment_timeout_minutes`, and **the cart TTL no longer applies** (GT-08c). `pay_timeout_at <= at` moves `PAYING → PAY_TIMEOUT` and releases inventory. Hold ids are client-supplied idempotency keys (`HOLD_ID_DUPLICATE`). Only the hold's customer may `RELEASE` or `PAY_START` it (`HOLD_NOT_YOURS`), offers included. | A hold that dies under a slow bank is the race every ticketing system has; the rule makes it a named outcome |
| D-13 | **Webhooks are idempotent and late money is refunded, never seated.** `PAY_SUCCEEDED` on `PAYING` → `CONFIRMED`, order and tickets issued, price = tier price at hold time, amount = `qty × (price + fee)`. On `PAY_TIMEOUT` → `PAID_AFTER_TIMEOUT`: a `Refund` of the full amount with that reason, no tickets (GT-08a). On `CANCELLED` → `PAID_AFTER_CANCEL`, likewise (GT-11c). Any webhook for a payment already settled → `PAYMENT_DUPLICATE`, no state change (GT-12). `PAY_FAILED` on `PAYING` releases the hold (`PAYMENT_FAILED_RELEASED`); a failed or timed-out hold cannot be paid again (`HOLD_NOT_HELD`). | Stripe delivers at least once and out of order; Goal 3 |
| D-14 | **Orphan rule.** An orphan is an `OPEN` seat whose left and right neighbours both exist and are both not `OPEN`. A hold is `ORPHAN_SEAT` when it would increase its row's orphan count (GT-05a); adjacent pairs, row-end singles (GT-05c) and filling an existing single (GT-05d) are fine. Switch: `rules.prevent_orphan_seats` (GT-05e). Seat ids are `<section>-<row>-<nn>`; a seat on another tier is `SEAT_TIER_MISMATCH`; GA tiers refuse seats (`SEATS_NOT_ALLOWED`), reserved tiers require them (`SEATS_REQUIRED`). | The one reserved-seating rule every venue has and every first build gets wrong; O-1 names the aisle variant |
| D-15 | **Waitlist: FIFO by `(joined_at, entry_id)`, `HEAD_BLOCKS`, offers are timed holds, `DROP` on expiry.** Join only when the target cannot serve you now — GA: `available < qty`; reserved: no contiguous block of `qty` in the section passes the orphan rule (`WAITLIST_NOT_NEEDED` otherwise, GT-18). Targets: a GA tier or a reserved section. One active entry per customer per target (`WAITLIST_DUPLICATE`). After every inventory return the fill runs per target: the head is offered when it fits, as a hold of kind `OFFER` with `offer_ttl_minutes`, then the next head is tested against what is left; **nobody behind the head is offered what the head could not use** (GT-09a). An ignored offer expires at its TTL; the entry becomes `OFFER_EXPIRED` and is dropped; the next head is offered in the same tick (GT-10). Declining (`RELEASE`) or a failed payment on an offer also ends the entry. A GA tier going off sale closes its waiting entries (`CLOSED_OFF_SALE`, W-5). `SKIP_TO_FIT` is refused by the schema. | Fairness you can explain at the window; O-3 is the TTL |
| D-16 | **Refunds are policy as data with integer rounding.** `refund_policy` is a list sorted by `min_days_before` descending and ending at 0; `days_before = floor((starts_at − at)/86400)` on the one axis; the first row with `min_days_before <= days_before` applies (GT-06). `refund_bps = 0` → `REFUND_WINDOW_CLOSED`. Amount per ticket = `price × refund_bps // 10000` plus the fee when `fee_refunded` (GT-07: 3499 → 1749, 1 cent stays with the venue). Refunds are per ticket; a refunded seat returns to inventory and the waitlist fills. Precedence: `ORDER_UNKNOWN` → `ORDER_NOT_YOURS` → `TICKET_NOT_IN_ORDER` → `TICKET_ALREADY_REFUNDED` → `TICKET_CHECKED_IN` → `REFUND_WINDOW_CLOSED`. | Goal 6; the odd price is deliberate so the floor is visible |
| D-17 | **Cancellation refunds everything.** `CANCEL_EVENT` refunds every `ISSUED` or `CHECKED_IN` ticket at `cancellation_refund_bps` **plus the fee**, cancels every `HELD`/`PAYING` hold, closes every waiting or offered entry, and makes every later command `EVENT_CANCELLED` except late webhooks (D-13) and a second cancel (`ALREADY_CANCELLED`). On the golden the venue's net is 0 (GT-11). | O-6 default: a cancelled show owes the checked-in guest too |
| D-18 | **Check-in precedence:** `TICKET_UNKNOWN` → `TICKET_REFUNDED` → `DOORS_NOT_OPEN` → `ALREADY_CHECKED_IN` (detail = first scan time) → `CHECKED_IN`. A checked-in ticket cannot be refunded (`TICKET_CHECKED_IN`, checked before the window). Ticket code = `sha256(event_id|ticket_id|ticket_salt)[:20]` (GT-02); signing is P1. | Goal 7's door half; the refused scan says *why* |
| D-19 | **Fixture generator is an event-queue simulation driven against the oracle.** Background demand (150 EARLY, 290 ADV, 190 BALC, 110 DOOR sessions; 32 refund attempts; 85 % check-in) and 79 named traps (T01–T79) run through one `Engine` so every id a later command references is the id the engine assigned. Customers `C-0001..C-0022` belong to the traps; section C's and DOOR's waitlists are reserved for traps T51–T61 and T66–T72. When a background command's time fell inside a running multi-step trap it was moved to the trap's current second (**154 commands clamped**); the shuffle proof shows order within a second is decided by `cmd_id`, not arrival. `answer_key.csv` holds 76 command expectations and 3 state assertions; `SOLD_OUT_TIER` is exercised 99 times by background demand and pinned by GT-04a rather than a trap. | The traps are the spec's hard cases; the background is there so they happen inside a realistic stream |

### Data model (Phase 2, shape fixed now)

| # | Decision | Why |
|---|----------|-----|
| D-20 | **Tables:** `Event` (rules JSON, salt, windows), `Pool`, `Tier`, `Section`, `Seat` (state `OPEN/HELD/SOLD`, `holdId`, `ticketId`), `Hold` (kind, state, customer, tier, qty, seats[], `createdAt`, `expiresAt`, `payTimeoutAt`, price and fee at hold time, `entryId`), `Payment` (Stripe `paymentIntentId`, amount, state), `Order`, `Ticket` (state, code, `checkedInAt`, `refundedCents`), `WaitlistEntry`, `Refund` (reason, Stripe `refundId`), `CommandLog` (every command and its result, `stripeEventId` unique when from a webhook). Timestamps are `CHAR(19)` strings with a `CHECK` regex (D-9). | Mirrors the engine's state one to one so the recount is a projection, not a translation |
| D-21 | **Append-only where it matters.** `CommandLog`, `Refund`, `Order` are immutable (UPDATE/DELETE rejected by triggers). `Hold`, `Payment`, `Ticket`, `Seat`, `WaitlistEntry` carry a `state` column guarded by a trigger that admits only the transitions in the brief's state tables; every transition also writes a `CommandLog` row in the same transaction. Nothing is deleted; a cancelled event keeps its rows. | Gavel/LoanBook/Quorum pattern; a count over mutable rows proves nothing, but seats and holds genuinely change state |
| D-22 | **Cast path: one transaction per command, `pg_advisory_xact_lock(hash(pool_id))` taken before the availability read.** `advance(now)` runs inside the same transaction against the event's rows before the command is evaluated. One test: two concurrent `HOLD`s for the last floor ticket → exactly one `HELD`, one `SOLD_OUT_POOL`. No further contention work (Gavel owns it). | The engine's "serialized stream" has to be made true by the database, and one lock per pool is enough at venue scale |
| D-23 | **Stripe boundary (`src/checkout/`).** `PAY_START` creates the `PaymentIntent` (amount from the engine, `metadata.hold_id`, idempotency key = hold id) and records `PAYING` only after Stripe returns; the webhook route verifies the signature per D-5, deduplicates on `event.id`, maps `payment_intent.succeeded` → `PAY_SUCCEEDED` and `payment_intent.payment_failed` → `PAY_FAILED`, and applies them through the cast path. Refunds call Stripe after the engine says `REFUNDED`, idempotency key = refund id; a Stripe failure leaves a `Refund` row in `PENDING_PROVIDER` for retry. In CI and in `inventory:eval:db` the Stripe client is replaced at the HTTP boundary by recorded fixtures in `fixtures/stripe/`. | Goal 3 made real against the provider's actual contract, without a key anywhere the agent runs |

### Phase 2 shape (Shane, 2026-11-10: "take the recommendations")

| # | Decision | Why |
